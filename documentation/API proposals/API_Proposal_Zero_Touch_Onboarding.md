# Zero-Touch Onboarding API Proposal

| **Field** | Description | 
| ---- | ----- |
| API family name | Zero-Touch Onboarding |
| API family owner | CableLabs |
| API summary | API to seamlessly onboard devices into a Trust Domain. <br><br> **Use Cases**: <br><br> - **Retailer** An online retailer sells devices with DPP/Matter capabilities. They use the Zero-Touch Onboarding API at purchase time to provision the device purchased by their customer so their access point is already provisioned when they receive it. The device seemlessly connects when turned on. <br><br> - **Medical Device Vendor**: A vendor selling medical devices receives an order from a hospital to send a health monitoring device to their patient. When fulfilling the order, they call the Zero-Touch Onboarding API to register the device allowing it to get connectivity as soon as it gets turned on by the patient. <br><br> **Terms:** <br><br> - **Trust Domain**: A Trust Domain represents a grouping of Devices which are allowed to directly interact with each other over the WiFi network as though they were on the same LAN. Trust Domains can be associated with particular policies as well. For example, some Trust Domains may require every Device contained in the Device Domain to have its own credential. And other Trust Domains may allow every Device to connect using the same credential - but only if explicitly confirmed or for a limited period of time. Trust Domains may also have their network linked to other networks - such as VPNs or other Device Domain networks, with or without limitations. <br><br> - **Device**: A device is a physical or virtual entity that can connect to a network. Devices can be provisioned to a Device Domain to enable secure communication with other devices in the Device Domain. <br><br> - **Provisioning**: Provisioning is the process of configuring a device to enable it to connect to a network. This process includes setting up network parameters, security credentials, and other configurations required for the device to communicate with other devices in the network. <br><br> - **Provisioning Protocol**: A provisioning protocol is a set of rules and procedures that define how a device can be provisioned to a network. Different devices may support different provisioning protocols, and a Device Domain may support multiple provisioning protocols.<br><br>  |
| Technical viability | Implementing this API requires a controller to manage the trust domains, services and devices logic as well as an agent running on the access point to provision. This agent has the responsibility to handle configuring the access point so the device can seemlessly onboard. | 
| Commercial viability | This API would allow telcos and 3rd party entities to offer an enhanced onboarding experience to their users. |
